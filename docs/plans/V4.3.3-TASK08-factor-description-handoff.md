本地实现：点击「智能匹配因子」，读取当前尚未保存的排放源描述并重新匹配。普通排放源与每个运输段分别读取自身 `remark`，不使用因子说明，不拼接 `name`。匹配结果仍写回既有因子字段，保存动作沿用原流程。

状态：本地代码已补充；远端接收、消费描述及真实匹配效果待对接和联调。本说明不代表远端已支持。

## 新增请求字段

| 字段 | 类型 | 必填 | 限制 | 含义 |
| --- | --- | --- | --- | --- |
| emissionSourceDescription | string | 否 | 最长200字 | 当前排放源描述；运输请求使用当前运输段描述 |

- 本地表单保存字段仍为 `remark`，仅匹配请求映射成 `emissionSourceDescription`。
- 未提供、null、空字符串或纯空白：按原有无描述匹配处理；本地后端移除此参数。
- 非空描述原文透传，不裁剪、不转小写、不用名称或因子说明补值。
- 本地按现有表单长度口径（UTF-16长度）限制200；超长或非字符串拒绝匹配，不静默截断。
- 不复用其他业务含义的 `description`，不改变现有响应结构、权限、匹配版本和来源偏好。

## 接口链路

前端 → SaaS：`POST /footprint3/factor/matchFactor`

SaaS 通过现有 Feign `${feign.url}` 转发请求 JSON：

| 场景 | 远端接口 |
| --- | --- |
| 普通排放源 | `POST /system/factor/queryFactorListAuthSearch` |
| 运输排放源（sourceType=2） | `POST /system/factor/queryFootprintFactorListAuthSearch` |

普通请求示例（仅展示业务参数，组织、签名等沿现有链路补充）：

```json
{
  "name": "纱线",
  "factorType": "3",
  "emissionSourceDescription": "再生聚酯纱线，数据来源为供应商年度生产记录"
}
```

运输请求示例：

```json
{
  "factorType": "3",
  "sourceType": "2",
  "transportType": "1",
  "way": "1",
  "emissionSourceDescription": "使用柴油货车运输，按实际货物重量和里程计算"
}
```

示例用于说明格式，不作为验收数据。运输仍沿用现有规则，不使用排放源名称检索。

1. 两个远端接口接收可选 `emissionSourceDescription`，检查其请求 DTO、参数白名单及后续组装过程不会丢字段。

4. 缺少描述时保持旧调用兼容；现有因子响应字段及无结果语义保持不变。

建议先上线远端支持，再发布本地调用方。接入前新增字段可能被忽略或被远端参数校验拒绝，不能将本地透传成功视为描述已生效。
