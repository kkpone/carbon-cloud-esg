# 赛事 Agent 页面

## 设计与实现范围

依据 [Figma 赛事页面](https://www.figma.com/design/ArMz3VWBBUdpwedrJoTtww?node-id=5021-26458) 的五个画板实现：大赛介绍、报名组别选择、企业信息填写、附件上传和审核状态。入口为 `/system/carbonCompetition/:code`，沿用现有赛事接口和 Agent 侧栏。

介绍页包含背景、目标、组别、CREOS 机制、奖项、赛程、合作伙伴及参赛服务入口。设计素材保存在 `src/assets/images/carbonCompetition`。页面组件、Less 模块和简体中文、繁体中文、英文文案按现有目录组织。

报名使用真实接口完成资料保存、稳定邀请链接生成、资质及 Logo 上传、草稿保存、提交人工审核和审核后进入名册。上传后展示文件名、大小和 Logo 预览；重新进入时通过已保存附件的授权下载接口恢复 Logo 预览。名册最多 10 人、至少 3 人确认报名等规则由服务端执行。

我的参赛任务参考 Agent 原型的 submit 页面，按 C/R/E/O/S 五卡并列展示。个人与企业组员仅提交 C/E，组长可提交五项；R/O/S仍需晋级和FINAL窗口。C保留两项核算和状态查看，E沿用真实打卡，R/O/S提供摘要、附件、保存草稿、确认提交及只读查看。窄屏横向滚动切换五项。

## 内容来源

- Banner 标题、副标题、背景、目标、完整规则、奖项补充说明、实际赛程和联系二维码使用已有后台配置。
- 设计稿 Banner 是占位区域，页面使用渐变背景、赛事标题和报名入口。
- 正式规则、联系二维码和合作单位未提供时，明确显示待公布；不使用设计稿中的示例二维码或合作 Logo。
- 企业 E 只统计本队有效入册成员，最多 10 人。赛程使用后台确认时间，不硬编码设计示例日期。

## 时间线配置

大赛时间线依据 [Figma 时间线画板](https://www.figma.com/design/ArMz3VWBBUdpwedrJoTtww?node-id=9022-3817) 实现九节点卡片、折返虚线和重点节点样式；窄屏改为纵向布局。设计稿日期仅用于隔离测试赛事，不作为正式默认值。

时间线内容最大宽度为 1124px，上排五个节点从左向右、下排四个节点从右向左，顺着折返箭头阅读。窄屏按正常时间顺序排为两列或单列。日期使用本地加载的 D-DIN 字体，字体及许可来自 [Datto D-DIN 字体仓库](https://github.com/amcchord/datto-d-din)，保存在 `src/assets/fonts/d-din`；正文沿用项目中文字体。折返线随上排高度调整，避免长文案与虚线重叠。

在 Boss 加载目标赛事，进入“时间线与任务赛程”，选择节点、填写北京时间，勾选“启用”和“确认本窗口时间”后保存。Agent 重新加载赛事数据即展示保存的日期；缺少配置、未启用或未确认时显示“待确认”。

| 展示节点 | 配置来源 |
| --- | --- |
| 报名开启、报名截止 | `REGISTRATION` 开始、截止时间，与实际报名窗口共用 |
| 赛前培训 | `TRAINING` 开始时间 |
| 初赛：产品碳足迹 | `C_PRODUCT` 开始、截止时间，与任务受理窗口共用 |
| 初赛：企业碳盘查 | `C_ENTERPRISE` 开始、截止时间，与任务受理窗口共用 |
| 初赛评审 | `PRELIMINARY_REVIEW` 开始、截止时间 |
| 初赛入围名单公布 | `PRELIMINARY_PUBLISH` 最早公示时间，仍需人工核验发布 |
| 决赛准备与答辩 | `FINAL` 开始、截止时间 |
| 最终结果公示 | `FINAL_PUBLISH` 最早公示时间，仅展示安排，不自动生成或发布最终结果 |

低碳打卡仍使用 `E_CHECKIN`，在任务页展示。阶段截止时间不包含该时刻；卡片显示日期，悬停可查看完整时间。培训、评审节点展示阶段安排；FINAL同时控制晋级企业R/O/S提交窗口，不自动生成晋级资格或决赛评分。

本次需更新 AI 服务、Boss 前端和 Agent 前端；复用赛事赛程表，无新增 SQL、环境变量或数据库时区变更。
